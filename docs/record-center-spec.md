# 记录中心（Record Center）— IA 优化 Spec

状态：待 Review（不进入开发）
范围：**纯 UI / 导航重构**——不新建表、不合并模型、不改 `VERSION`、不动 CareNote 的归属/状态/关联与安全规则。
关联：`docs/care-notes.md`（冻结规格）、`docs/todos.md`、`docs/family-mvp.md`。

## 1. 目标与非目标

**目标**
1. 保留现有 **5 个底部 Tab**，把「日记」升级为「**记录**」，统一承载**身心日记 + 照护笔记**的浏览与新增。
2. **减少记录时的步骤**：统一浏览、分类筛选、**基于上下文的快捷新增**。
3. 「今日」继续作为**执行中心**（服药 / 照护事项 / 待办），只做**管理入口**的轻度优化。

**非目标**
不合并领域模型；不新增首页区块；不新建表 / 不改 schema；不引入标签体系、AI 或 Note↔Todo 联动；不把参考知识搬上首页；不改 CareNote 既定的归属恒可见、个人观察中性、SUPERSEDED 折叠但可搜、悬挂容忍、不排闹钟等规则。

## 3. 关键设计决策

**D1 — 保留 5 个 Tab，只把「日记」升级为「记录」。**
理由：5 已是移动端底部导航的**上限**（Material 硬上限 5、HIG 建议 3–5），而"把主要目的地藏进 overflow"有实测代价（可发现性近乎腰斩）。本次不冒险降级为 4 个，因为那会要求把 `历史`（每天要看的依从率）塞进别处，**给高频动作增加一次点击**——收益与代价不成正比。
**取舍**：顺带修掉"tab 叫日记、页面叫身心记录"的名实错位（改标签为「记录」），这是**修正**而非让用户重新适应。

**D2 — 记录中心 = 一个统一浏览面 + 两个模式（模型不合并）。**
- 顶部 chips：`全部 / 身心记录 / 照护笔记`（沿用本仓 chips 惯例，不引入嵌套 tab）。
- 默认「全部」= **按时间倒序混排**两类记录（条目样式区分类型）；本质是 **UI 层合并**，与今日页把药与照护事项混排为统一时间轴是同一手法（既有先例，不新增模型）。
- 「照护笔记」模式下追加**既有**的搜索与状态筛选；日记模式可按评分/是否有关联药品筛。
- **数据边界**：`SymptomLog`（日期流水）与 `CareNote`（带归属与状态的知识条目）各自独立成表、独立编辑、独立校验；记录中心只做**读取与路由**，不产生第三张表，也不做跨表写入。

**D3 — 减少步骤：新增入口按"当前语境"决定。**
- 在「全部」模式点 ＋ → 让用户选类型（两项大按钮，两步）；在某一模式点 ＋ → **直达该类型编辑器**（一步）。
- **上下文快捷新增**（本条最能减少步骤）：药品详情 / 照护事项详情 / 待办详情的既有「相关笔记」卡片上提供「＋ 新建笔记」→ **直接打开编辑器，且关联对象已预挂**（编辑完保存即完成，无需再回列表去挂关联）。
- 编辑器本身不变：照护笔记保持归属四选一（默认 `PERSONAL_OBSERVATION` + 强引导）、正文逐字、可选名称/时间/出处、多选关联、状态默认 `ACTIVE`；日记保持既有字段。

**D4 — 今日页只做"入口优化"，不加区块。**
- 复用既有区块承载入口：待办区块的「查看全部 n 条」改为同时承担"管理"（或并置一个「管理」）、照护事项时间轴段标题旁加「管理照护事项」、`更多` 里保留「照护笔记」（指向记录中心）。
- **硬约束**：首页区块顺序不变、**不新增区块**——首页每多一块，安全关键的服药时间轴就下沉一分（研究：仪表盘职责是"快速给出关键信息"，失效模式是优先级被冲淡与警觉疲劳；本项目也已把这条写进 `docs/care-notes.md:128`）。

**D5 — 与既有规格的一致性**：CareNote 的归属恒可见（含名称为空）、个人观察中性框架（不得改写成因果）、`SUPERSEDED` 折叠但显式搜索仍返回并标「已被更新」、悬挂关联容忍、**不排任何闹钟**——**逐条保持不变**，记录中心只是多了一个浏览入口。

## 4. 页面交互

**4.1 记录中心（`Route.Diary` → 建议更名 `Route.Records`，label「记录」）**
1. 顶部：标题「记录」+ 搜索框（沿用照护笔记既有搜索样式）。
2. 其下：模式 chips `全部 / 身心记录 / 照护笔记`。
3. 主体：时间倒序列表。
   - 照护笔记条目：标题、正文摘要、**归属行（类型恒显 + 名称/时间可选）**、状态 chip（`待确认` / `已被更新`，后者折叠其更新说明）。
   - 身心记录条目：日期、总评、症状/副作用摘要、备注。
   - 空态：整段不渲染列表壳（只留一句引导 + ＋），不留空标题。
4. 右下 ＋：按 D3 规则决定"选类型"或"直达编辑器"。

**4.2 照护笔记模式**：列表 + 既有搜索 + 行内动作（编辑 / 待确认 / 已更新 / 恢复 / 删除），与现状一致。
**4.3 身心记录模式**：列表 + 既有编辑器（评分 / 症状 / 副作用 / 备注 / 关联药品），与现状一致。
**4.4 上下文快捷新增**：三个详情页的「相关笔记」卡片增加「＋」；日记的上下文入口暂不做（无自然挂载点，避免过度设计）。

## 5. 导航与数据边界

- **导航**：仍为 5 个顶层目的地；`Route.Diary` 语义升级为记录中心（建议常量更名，仅内部引用，外部意图不依赖任何 tab 名——已核实）。日记/笔记编辑器仍为各自独立路由，从记录中心与详情页两处可达。
- **数据**：不新增表、不新增列、不改 `VERSION`；**无 schema 迁移、无备份兼容影响**。
- **安全**：CareNote 的归属与状态规则、悬挂容忍、不排闹钟**逐条不变**。

## 7. 实施范围（分阶段，各自可独立验收）

- **R1 记录中心（只读）**：tab 标签与路由改造 + 记录中心屏（chips + 混排时间轴 + 搜索 + 空态）。
- **R2 新增体验**：统一 ＋（按模式直达）+ 三个详情页的上下文快捷新增。
- **R3 今日入口优化**：待办区块与照护事项段的"管理"入口（**不加区块**）。
- **不做**：第 4 个 tab 的进一步合并（含把 `历史` 并入「我的药品」）、模型合并、标签体系、AI、Note↔Todo、修 `history_shortcut` 空操作。

## 8. 验收标准

1. 记录中心能**混排浏览**两类记录，chips 切换后**只显示该类型**，搜索与筛选正确；
2. **步骤数**（可测）：从药品详情到"一条已挂该药关联的笔记保存完成" **≤ 3 次交互**；在「照护笔记」模式下从记录中心到编辑器 **1 次**；在「全部」模式下 **2 次**（先选类型）；
3. **归属恒可见**：任一条目（含未填名称）在列表与卡片上都显示归属类型；
4. `SUPERSEDED` 默认折叠，但显式搜索仍返回并标「已被更新」；
5. 顶部导航仍为 **5** 个；**无 schema 变更**（不产生 `24.json`）；既有测试全绿 + 新增列表/筛选/空态/快捷新增的 VM 与 UI 测试；
6. 真机验收：记录中心混排与筛选、上下文新建（含预挂关联）、空态、以及**既有首页组合与用药/照护/待办回归**（首页 dump 与改造前一致）。
