# 记录中心（Record Center）— IA 优化 Spec（冻结版）

状态：**已冻结（不进入开发）**；模型级改动须新开评审。
范围：**纯 UI / 导航重构**。不新建表、不合并模型、不改 `VERSION`（**本次不产生 `24.json`、无迁移、无备份兼容影响**）。
关联：`docs/care-notes.md`（冻结规格）、`docs/todos.md`、`docs/family-mvp.md`。

## 0. 已确认决策（Review 通过）

1. Tab 名使用「**记录**」（替代「日记」）。
2. 记录中心**默认进入「全部」混排模式**。
3. `Route.Diary` 更名为 `Route.Records`，**且须保持必要的路由兼容**（检查项见 §5）。
4. **保留 5 个 Tab**，暂不合并「历史」。

## 1. 目标与非目标

**目标**：保留 5 个底部 Tab；把「日记」升级为「记录」，统一承载**身心日记 + 照护笔记**的浏览与新增；**减少记录步骤**（统一浏览、分类筛选、**基于上下文的快捷新增**）；「今日」仍是执行中心，只做管理入口优化。

**非目标**：不合并领域模型；不新增首页区块；不新建表 / 不改 schema；**不为身心记录新增任何筛选/搜索功能**（现无此能力，本次不引入）；不加标签体系、AI、Note↔Todo 联动；不改 CareNote 既定的归属/状态/关联/安全规则。

## 3. 关键设计决策

**D1 — 保留 5 个 Tab，只把「日记」升级为「记录」。**
5 已是底部导航上限（Material 硬上限 5、HIG 3–5），而"把主要目的地藏进 overflow"有实测代价（可发现性近乎腰斩）。顺带修掉名实错位（标签「日记」→「记录」）。**`enableSymptomDiary` 语义保留**：关闭时该 Tab 仍按既有逻辑隐藏。

**D2 — 记录中心 = 一个浏览面 + 两个模式（模型不合并）。**
- 顶部 chips：`全部 / 身心记录 / 照护笔记`（沿用本仓 chips 惯例，不引入嵌套 tab）。
- 数据边界：`SymptomLog`（日期流水）与 `CareNote`（带归属与状态的知识条目）**各自独立成表、独立编辑、独立校验**；记录中心只做**读取与路由**，不产生第三张表、不跨表写入。

**D3 — 「全部」模式的跨类型搜索、筛选与 SUPERSEDED 可见性（修订 1）**
| 项 | 规则 |
|---|---|
| 搜索范围 | 一个搜索框，**跨两类**：`CareNote` 匹配 `title`/`body`/`attributionName`；`SymptomLog` 匹配备注与症状/副作用文本。结果仍按混排规则排序 |
| 筛选 | **仅 chips 的类型切换** + 照护笔记**既有**的状态筛选。**不为身心记录新增筛选**（现无此能力，见 §2） |
| SUPERSEDED 可见性 | 与 `docs/care-notes.md` 一致：**默认折叠**；**显式关键词搜索命中时必须返回**并标「**已被更新**」（可展开更新说明）。该规则在**全部模式与照护笔记模式内一致**；身心记录无状态概念，不受影响 |
| 空态 | 无任何记录时**不渲染列表壳**（只留引导语与 ＋），不留空标题 |

**D4 — 减少步骤：新增入口按当前语境决定（修订 2、4）**
- 「全部」模式点 ＋ → 先选类型（2 次）；某一模式点 ＋ → **直达该类型编辑器**（1 次）。
- **上下文快捷新增**：药品/照护事项/待办详情页的既有「相关笔记」卡片加「＋」→ **直接打开编辑器且关联已预挂**，保存即完成。
- **成员归属校验（硬规则）**：预挂关联前必须校验**目标对象 `careRecipientId` == 当前 `ActiveRecipientStore` 成员**；不一致**不预挂**并给出中性提示（如"该对象属于其他成员，已取消预挂关联"），**绝不写入跨成员关联**。无当前成员（`NO_RECIPIENT`）时按既有约定**读空、写抛错**，不进入写入路径。
- 编辑器不变：照护笔记保持归属四选一（默认 `PERSONAL_OBSERVATION` + 强引导）、正文逐字、可选名称/时间/出处、多选关联、状态默认 `ACTIVE`；日记保持既有字段。

**D5 — 今日页只做"入口优化"，不加区块。**
复用既有区块：待办区块的「查看全部 n 条」兼作管理入口；照护事项时间轴段标题旁加「管理照护事项」；`更多` 保留「照护笔记」（指向记录中心）。**硬约束**：首页区块顺序不变、**不新增区块**（每多一块，安全关键的服药时间轴下沉一分；与 `docs/care-notes.md:128` 一致）。

**D6 — 混排的时间字段与排序（修订 3，硬规则）**
| 项 | 规则 |
|---|---|
| 时间字段 | 身心记录用 **`recordedAt`（事件时间）**；照护笔记用 **`createdAtMs`（记录创建时间）**。混排一律用"事件时间" |
| 排序 | 事件时间**倒序**；同值时以类型固定顺序（照护笔记优先）+ `id` 倒序，保证**稳定可复现** |
| **`updatedAtMs` 不参与混排排序** | 理由：**避免编辑一条旧笔记后它跳到时间轴最前、被误认为今天的记录**；编辑只更新内容 |
| 编辑的可见表达 | 被编辑过的条目在**原位**显示轻量「已编辑」提示（已实现则沿用；未实现属可选加分项，不做硬要求） |
| 与照护笔记模式的差异 | 照护笔记模式**保留既有排序**（`QUESTIONABLE` > `ACTIVE` > `SUPERSEDED`，同级按 `updatedAtMs` 倒序）——类型内部"待确认优先"有意义；**混排视图不采用该规则**。两套排序的差异**须在实现处加注释说明**，避免日后被"统一"掉 |

## 4. 页面交互

**4.1 记录中心**（`Route.Records`，label「记录」）：标题「记录」+ 搜索框 → 模式 chips → 时间倒序列表（照护笔记条目：标题/正文摘要/**归属行（类型恒显 + 名称/时间可选）**/状态 chip；身心记录条目：日期/总评/症状摘要/备注）→ 右下 ＋（按 D4）。空态见 D3。
**4.2 照护笔记模式**：列表 + 既有搜索 + 行内动作（编辑/待确认/已更新/恢复/删除），与现状一致。
**4.3 身心记录模式**：列表 + 既有编辑器，与现状一致；**不新增筛选**。
**4.4 上下文快捷新增**：三个详情页的「相关笔记」卡片加「＋」（含 D4 成员校验）。日记的上下文入口**不做**（无自然挂载点，避免过度设计）。

## 5. 导航与数据边界

- **导航**：仍 5 个顶层目的地。`Route.Diary` → `Route.Records`，**路由兼容检查项（均已核实通过）**：① 无深链/`navDeepLink` 依赖路由名（`shortcuts.xml`、`AndroidManifest.xml` 均无）；② 无持久化导航状态依赖路由名；③ 通知/小组件/二维码/开机均以启动意图进入，不点名 tab（唯一点名者是 `Route.AddMedication`，不受影响）；④ 内部引用（NavHost、`更多` 菜单、`enableSymptomDiary` 过滤）随改名同步更新；⑤ **两处钉桩测试随改名更新**（有意更新，非绕过）。
- **数据**：不新增表/列、不改 `VERSION`、**无迁移**。
- **安全**：CareNote 归属恒可见（含名称为空）、个人观察中性框架、SUPERSEDED 折叠但可搜、悬挂关联容忍、**不排任何闹钟**——逐条不变。

## 7. 实施范围（分阶段）

- **R1 记录中心（只读）**：label 与 route 改名 + 记录中心屏（chips + 混排时间轴 + 跨类型搜索 + 空态）。

## 8. 验收标准

1. 混排正确：两类记录按**事件时间**倒序混排；chips 切换后只显示该类型。
2. **排序可证（修订 3）**：编辑一条旧笔记（改正文/状态）后，它在时间轴中**位置不变**（不因 `updatedAtMs` 跳到最前）。
3. 跨类型搜索：一个关键词能同时命中两类；`SUPERSEDED` 默认折叠，但被搜索命中时返回并标「已被更新」。
4. **点击次数口径（修订 4；明确区分"导航点击"与"输入/保存"）**：
   - 从**药品详情**到"编辑器可用且关联已预挂"= **1 次导航点击**（卡片上的 ＋）；
   - 完整保存一条笔记 = 上述 1 次 + **内容输入（不计入导航口径）** + **1 次保存**；
   - 从记录中心「照护笔记」模式到编辑器 = **1 次**；从「全部」模式 = **2 次**（先选类型）。
5. **成员归属（修订 2）**：在**非当前成员**的对象上触发快捷新增时，**不产生跨成员关联**（须有测试覆盖）。
6. 归属恒可见（含未填名称）；首页仍无新区块；顶部导航仍 **5** 个。
7. **无 schema 变更**（不产生 `24.json`）；既有测试全绿 + 新增列表/混排/搜索/空态/快捷新增的 VM 与 UI 测试。
8. 真机验收：混排与筛选、跨类型搜索与 SUPERSEDED 命中、上下文快捷新增（含预挂关联）、编辑旧笔记后位置不变、以及**既有首页组合与用药/照护/待办回归**（首页 dump 与改造前一致）。
